# 录音（Fuyu 插件）

Windows 专用的浮屿录音插件。点岛上的「录音」页开始，点「停止并保存」得到 WAV 文件；文件自动加入浮屿的文件中转，并在岛上弹出通知。录音中可以暂停/继续，页面和收起条同步显示状态与时长。快捷键 `Ctrl+Alt+R` 开始/停止，`Ctrl+Alt+P` 暂停/继续。

状态共六种：未开始、启动中、录音中、已暂停、已结束、出错。时长由宿主计时并每 500ms 推送快照，收起条和页面读同一份数据，不会各走各的。权限不足、设备不可用、进程中断分别给出对应提示；中断时若 WAV 已落盘会自动补交到文件中转。

录音期间会按住系统的电源请求（`SetThreadExecutionState`），避免长时间录音被自动休眠打断；页面下方列出最近 20 段录音，点一条直接在资源管理器里定位。

## 安装

到 [Releases](https://github.com/wai023/recorder/releases) 下载最新的 `wai023-recorder-*.fuyu`，双击安装。浮屿若拦第三方插件，先在设置里放开。

包内只有 JS 和一个 PowerShell 脚本 `assets/record.ps1`，不带 `.exe` / `.dll`，不依赖 ffmpeg。

## 原理

插件宿主是 Node 进程，启动一个常驻的 PowerShell 子进程，通过 stdin/stdout 收发命令。PowerShell 脚本 `assets/record.ps1` 随包分发，运行时复制到插件数据目录；它调用 Windows 自带的 `winmm.dll` MCI 接口录音并直接保存为 WAV。

不依赖 ffmpeg，不在包内携带任何 `.exe` / `.dll`。插件与浮屿同权，无沙箱。

## 它读什么、写什么、连什么

- 读：自身数据目录 `ctx.dataDir` 下的 `record.ps1`；录音列表会读数据目录与所选保存目录里的 `*.wav`
- 写：`ctx.dataDir` 下的 `record.ps1`；录音文件写在「保存位置」选定的目录，默认是数据目录
- 运行：`powershell.exe`（Windows 自带）；停止/定位文件时调用一次 `explorer.exe /select`
- 联网：无

## 收起条配置

点收起条项右侧的小齿轮，或在录音页点「设置」，打开插件设置：

- **收起条样式**：`icon`（仅麦克风图标）、`icon-time`（图标加时长，默认）、`text-time`（文字加时长）
- **显示状态点**：用圆点颜色区分待机、录音中、已暂停、已结束、出错
- **保存位置**：`data`（插件数据目录，默认）、`music`、`desktop`、`documents`；目录建不出来时自动退回数据目录

配置变更走宿主侧的 `ctx.config.onChange`，保存后立刻推给岛上；另有 10 秒一次的文件轮询兜底，旧版浮屿也能用。

录音结束后当前时长归零，最后一次时长单独留在录音页显示；收起条不再挂着旧读数。

## 面板组件

录音已注册为面板小组件。在岛上展开的 Fuyu 页点底部「添加组件」，在「插件」分组里找到「录音」，点右侧的加号即可加到网格面板；也可以从底部组件栏直接拖进去。组件支持 1×1、2×1、2×2、4×1 四种尺寸，显示状态、实时时长和开始/暂停/停止按钮，宽尺寸下还有设置入口。组件与页面、收起条共用同一份宿主状态，不会出现各走各的计时。

插槽 `island.widget/v1` 必须在 `package.json` 的 `fuyu.slots` 里声明，组件才会出现在设置窗口的「可以添加」清单里（设置窗口不加载插件代码，宿主按清单声明上报 widget 元数据）。主面板底部的「添加组件」栏读的是运行时实际注册的条目，与设置清单是两条链路。

代码里用 try/catch 注册该插槽，旧版浮屿会安全跳过，页面和收起条照常工作。**注意 `ctx.slots.add` 依赖 `this`**：必须直接在 `ctx.slots` 上调用（或用 `.call(ctx.slots, ...)`），不能先赋给局部变量再调用，否则抛 `Cannot read properties of undefined (reading 'ctx')`，被 try/catch 吞掉后主面板清单里不会出现录音。widget 的 id 与岛页面同为 `recorder`，`sizes` 含 `bar`，与官方天气插件写法一致。

本地 SDK 2.1.0 的校验器尚未收录这个插槽，`npm run check` 会报一条 `unknown-slot`；浮屿 0.3.12 主程序实际支持，属校验器滞后，不影响运行和手动安装。

## 最近录音

录音页底部列出最近的录音（最多 20 条，按修改时间倒序），每行显示时间、时长、体积，点一下用 `explorer.exe /select` 在资源管理器里定位。列表由宿主读目录生成，时长直接解析 WAV 头（`src/wav.ts`），只读前 512 字节，不把整段音频读进内存。

窗口侧只能通过 `recorder.reveal` 传路径，宿主会校验目标必须是「已知录音目录里的 `.wav`」，避免任意路径被拉起来。

## 开发

```sh
npm install
npm run dev        # 需浮屿正在运行
npm run typecheck
npm run lint
npm run test       # 21 项：协议解析、配置归一、WAV 头解析、宿主初始化、端到端状态机
npm run check
npm run package    # 产出 .fuyu
```

## 已知限制

- 仅支持 Windows（macOS 未适配）
- 录音成功依赖系统存在可用的麦克风设备；MCI 报告的采样率在部分驱动上可能回落到默认值，但生成的 WAV 文件有效
- 首次运行需要 Windows 允许 PowerShell 执行本地脚本（子进程使用 `-ExecutionPolicy Bypass`）
- 自动化测试用假子进程模拟 MCI，不依赖真实麦克风；真机录音仍需在浮屿里点按钮验证一次
- **选不了麦克风**：MCI 的 `waveaudio` 只认系统默认录音设备，没有设备参数；要选设备得换 WASAPI 重写录音栈
- **没有实时电平/波形**：同一个原因，MCI 不暴露电平数据
- **防休眠只挡自动睡眠**：合盖、手动睡眠、关机仍会中断录音；中断时若已落盘会自动补交文件，但正在缓冲的部分会丢（MCI 只有 `STOP` 才写盘）
